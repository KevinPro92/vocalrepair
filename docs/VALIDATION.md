> 素材由作者本人录制（有绝对音感），4 段，均为清唱，m4a → WAV（ffmpeg，44.1 kHz 立体声）。
> 原始录音**不入库**（`.gitignore` 中的 `demo/`），只在此记录测量结果。

| A | `F大调小星星，偏低` | F 大调 | 整体偏低跑调 |

## 2. 三方算法交叉验证（先证明测量本身可信）

同一段音频、同一帧网格（10 ms），三种**原理完全不同**的基频估计器：

| 素材 | 我们（多候选 YIN + Viterbi） | 经典 YIN | **pyworld.harvest**（第三方独立实现） | f0 中位数（三者） |
|---|---|---|---|---|
| A 偏低 | 21.71 | 21.75 | 23.30 | 221.5 / 219.8 / 218.7 Hz |
| B 偏高 | 23.67 | 25.89 | 23.61 | 239.7 / 243.4 / 238.9 Hz |
| **C 不跑调** | **12.13** | 16.07 | 14.63 | 258.0 / 255.9 / 255.3 Hz |
| D 破音 | 24.47 | 24.67 | 23.51 | 350.3 / 350.3 / 346.8 Hz |

*表中数字 = 相对最近半音的音分偏差，取浊音帧的**中位数**。*

**结论**：
- 三者对每一段的排序与量级完全一致（差 1–2 cents），f0 中位数相差 < 5 Hz（< 0.3 %）
  → 说明我们的测量不是自说自话，第三方的独立实现给出同样的答案
- **"不跑调"那段确实是四段中最准的（12.1 cents）**，与作者自述一致
- 我们的多候选 Viterbi 比经典 YIN 略优（12.13 vs 16.07），说明全局路径平滑确实有效

## 3. 调性估计（修复后的结果）

| 素材 | 估计结果 | 置信度 | 与自述 |
|---|---|---|---|
| A 偏低 | **F major** | 0.88 | ✅ 一致 |
| B 偏高 | A# major | 0.52 | ⚠️ 不一致（整段音级上移，置信度也低） |
| C 不跑调 | **G major** | 0.92 | ✅ 一致 |
| D 破音 | F minor | 0.41 | 主音一致，调式误判为小调 |

> 修复前用**频谱色度**估计，四段全部错位（F→G#、G→D#、F→G#）。根因是谐波被算到错误音级上
> （唱 F3 时三次谐波是 C5、五次是 A5）。改用**音高驱动的色度**（只数 f0 的 pitch class）后，
> 主音 3/4 正确。这验证了"单声部不该从频谱里猜音级"这一判断。

## 4. 修音链路实测

参数：`strength=0.7`，`auto_strength=True`（新），`pitch_adaptive_deadzone=True`。

| 素材 | 音准中位偏差 前 → 后 | Δ | 被修正帧 | octave 守护残差 | LTAS 相关 |
|---|---|---|---|---|---|
| A 偏低 | 21.71 → **19.43** | **−2.28** | 631 / 1076 | +4.1 | 0.990 |
| B 偏高 | 23.67 → **21.46** | **−2.21** | 749 / 972 | −58.8 | 0.969 |
| C 不跑调 | 12.13 → **12.80** | **+0.67** | 247 / 856 | −6.2 | 0.991 |
| D 破音 | 24.46 → **21.88** | **−2.58** | 470 / 1083 | −192.7 | 0.967 |

**解读**：
- 三段跑调素材都得到改善（−2.2 ~ −2.6 cents），音色保持良好（LTAS 0.967–0.991）
- 需要修正的三段里，仍有 **17–29 % 的浊音帧未被改动**（死区生效，保留表现力）
- 对照组 C 只变化 +0.67 cents（第一版为 +2.04，属明显副作用），说明**过度修音问题已缓解**
- 所有段落的 octave 守护残差都远小于 600 cents 阈值，未触发安全回退

## 5. 发现的问题（诚实记录）

### 5.1「破音」不是数字削波
4 段素材的削波样本数都是 **0**（阈值 0.98），包括自述"破音"的那段。
说明那是**声带层面的破音/破裂音（vocal break）**，不是波形削顶——两者是完全不同的现象：

| 类型 | 物理表现 | 当前是否支持 |
|---|---|---|
| 数字削波 | 波形顶部被截平，产生宽频奇次谐波 | ✅ 支持（检测 + 样条重建） |
| 声带破音 | 短时周期性崩塌（HNR 骤降、f0 跳变、气声突增） | ❌ **未支持**，列为 v0.4.3 |

### 5.2 参考材料的偏差分布是"混合型"
中位偏差 12 cents 的素材里，P95 仍达 41.7 cents，说明**段内并非所有音都准**：
一部分音接近 0，另一部分偏 40 左右。段级目标（每段一个目标音）无法表达这种细结构，
这是"修正后仍有残留偏差"的主要原因，也是 v0.4.3 要改成**音符级目标**的动机。

### 5.3 偏高段的 octave 守护残差偏大（−58.8 ~ −192.7 cents）
虽然低于 600 cents 阈值（未回退），但比对照组（−6.2）大得多。可能原因：
修正后音高整体上移、WORLD 重合成在弱声段产生偏差。**需要进一步核查**。

### 5.4 PSOLA「失声」bug（已修复）

用户在听感反馈中指出：psola 引擎下"一闪一闪亮晶晶"出现整字失声。定位到两处实现错误：

| bug | 原因 | 修法 |
|---|---|---|
| 整字失声 | 合成步长取 `sr / tgt_f0`，而**清音段 tgt_f0 = 0** → 步长 = 1 秒，一步跳过整个字（辅音正是清音） | 清音段固定用"浊音中位周期"推进；步长硬限制在 [1 ms, 25 ms] |
| 尾部丢失 | 边界处 `break` 直接终止整个合成循环 | 只跳过该帧，循环继续 |

验证方式：直接比对**输入有声而输出静音**的区间（阈值 25 dB，>30 ms 才算）：

```
偏低   失声段 0 个
偏高   失声段 0 个
不跑调 失声段 0 个
```

### 5.5 Praat 式基音标记（已实现）

上一版在原始波形上取 `argmax(|x|)` 会**锁到谐波峰**（人声一个周期内有 F1/F2/F3
多个峰），这是用户直觉"人声有高低频泛音，机器难以判断"的准确对应。改为 Praat 的做法：

1. 按 f0 中位数把信号**零相位低通到 1.5×f0**（谐波被削掉，只剩每周期一个基音峰）
2. 在低通信号上找正向局部极大
3. 周期一致性校验：间隔在 [0.6T, 1.6T] 之外的峰判为误检/漏检
4. 漏检处按周期等距插值补齐

### 5.6 三种合成引擎的取舍（实测，strength 0.7）

| 素材 | none（仅削波） | psola | world |
|---|---|---|---|
| F大调_偏低 | 21.71 | **18.68** | 19.11 |
| F大调_偏高 | 23.67 | **19.96** | 20.09 |
| G大调_不跑调 | 12.13 | 13.57 | **12.71** |
| 黑色幽默_破音 | 24.46 | **21.39** | 22.35 |

*数字为相对最近半音偏差的浊音帧中位数（cents），越小越好。*

结论：
- **psola** 在 3/4 素材上音准最好，且不做参数化重合成（音色/噪声纹理天然保留）；
  但仍会小幅降低 HNR（0.5–1.3 dB），且对照组（本来就准）有 +1.4 cents 副作用
- **world** 音准次之但稳定，代价是对高气声素材有可闻的"水声"
- **none** 音质最好（完全不碰音高），可作为"最小干预"对照

用户听感裁定（真实录音，带耳机）：
- 音准：world 略优于 psola
- 音质：none 最好；world 有噪点但"带伴奏后影响会小很多"
- psola 修复前的失声问题 → 已解决
